Abstract

What was tested?

This study asks whether a compact set of public-safe search and content signals can rank pages for human review when the observed data contains an associated performance-decline label. I use the FlyRank anonymized starter release of 30,000 pseudonymized content items with 90-day activity and content-context fields. I compare a transparent rule baseline with logistic regression, a decision tree, and a random forest using a client-aware holdout, while excluding label-derived trend fields and pseudonymous IDs from the feature vector. In the bundled reference run, Precision@50 was 0.240 for the baseline and about 0.740 for the random forest, with a 0.542 decline-label base rate. The resulting ranked queue is decision support for human review and signal discovery, not a causal estimate of traffic impact or a prediction of Google's ranking system.

Problem

A ranking problem, not an autopilot

When review capacity is limited, an editor needs an ordered queue. The system scores each pseudonymized content item, attaches reason codes, and suggests a review category. The human still verifies the page and decides whether to act.

Unit

One pseudonymized content item.

Output

Risk score, rank, confidence, and reason codes.

Decision

Inspect, review metadata, expand, refresh, or monitor.

Data & Methodology

Designed around leakage control

Data

Public-safe anonymized starter release with about 30k items and 90-day aggregates.

Label

trend_direction == "down". This is a snapshot-derived proxy, not a clean future outcome.

Excluded

Trend fields, IDs as features, and future/overlapping outcome fields. Client ID is grouping-only.

Baseline

Transparent score combining visibility, freshness, position opportunity, and content depth.

Models

Logistic regression, decision tree, and random forest.

Validation

Client-aware holdout to reduce the risk of learning client-specific patterns.

Interpretation

What the model is actually seeing

The leading observed signals include days with impressions, logged impressions, average position, content age, content length, clicks, CTR, and engagement measures. In this dataset, these signals help distinguish rows associated with the decline label. They should be treated as associations used for prioritization—not levers proven to cause an outcome.

Ranked Recommendations

Turn a score into a review playbook

01
Inspect high-confidence multi-signal pages

Start with pages supported by several reason codes rather than a single noisy signal.

02
Review visible low-CTR pages

Check title/snippet and search-intent alignment before changing the page itself.

03
Inspect thin visible pages

Check completeness and intent coverage before expanding content.

04
Review engagement candidates

Inspect usefulness and page experience before changing copy.

05
Monitor low-confidence items

Wait for stronger evidence instead of turning every score into an automatic action.

Limitations

What this study cannot prove

Snapshot proxy

The decline label is derived from the observed snapshot, not a clean future-window outcome.

No causal effect

The design cannot show that refreshing a page causes better traffic, ranking, clicks, or engagement.

Scope

Results describe this anonymized release and should not be generalized to every site or search system.
